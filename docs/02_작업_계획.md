# 잔흔(Scars) — 작업 계획

2026-10-03 작성, 10-06 서재 제한 시간(M3-1) 추가. 흐름 정본은 `할 일1.pdf`, 코드 구조는 `01_코드_구조.md`.

## 역할

- **백엔드 + 약간의 프론트**: 게임 로직(순수 C#), EditMode 테스트, 조작 처리(ScreenStack·InputRouter)
- **클라이언트 + QA**: 씬·화면(View)·연출, 실제 내용 데이터 입력, 엔딩 경로 QA

## 원칙

1. **다른 기능이 많이 의존하는 것부터** 만든다.
2. **서로 기다리지 않는다.** 뼈대의 공개 함수 이름이 두 사람 사이의 약속이다. View는 로직 클래스의 공개 함수만 부르고, 이름을 바꿔야 하면 먼저 알린다.
3. **끝까지 플레이되는 한 줄기**를 먼저 만든다 (단서 하나 → 가설 → 심문 → 엔딩).

## 0단계 (같이)

- 뼈대 커밋·푸시 후 각자 브랜치에서 작업, `main`에는 PR로 합친다.

### M3-1 메모

- 명세: `잔흔 [시스템 추가] Phase 3 서재 조사 제한 시간 (7분) 명세.pdf`, 보완: `시간 제한 상세.docx`
- 7분·대사 같은 내용은 코드가 아니라 PhaseData·대화 에셋에 넣는다. 경감의 최후통첩 대사는 Phase 2 대화 데이터라 코드가 필요 없다.
- `Time.timeScale`은 쓰지 않는다 (빗소리·연출까지 멈춤). 타이머는 바깥 Update가 Tick으로 시간을 넣는다.
- 단계 경계는 화면에 보이는 초(올림) 기준: 경고 ≤ 1:59, 마지막 1분 ≤ 0:59, 위험 ≤ 0:29.
- ⑥-1은 다른 코드에 의존하지 않아 ⑥ GameManager보다 먼저 만들 수 있다. ⑥-3은 ⑥과 함께 한다.
- 경감 대사의 (플레이어 이름)은 ⑤에서 미룬 `{player}` 치환과 같은 문제 → 플레이어 이름 저장 위치를 ⑥에서 정한다.

**확정 (10-06)**

- 시작: 서재에 들어와 **마우스로 방향 조작이 가능해지는 순간** 카운트다운 시작.
- 멈춤: 인물 일지(C) · 단서 상세 창 · 가설 조립 창(Tab) · **ESC 메뉴 · 대화 중 · 판별 질문(선택지 팝업)**. 겹쳐 열 수 있으므로 이유별로 센다.
  - 판별 질문은 팝업이 뜨는 순간 멈추고, 선택지를 클릭해 카드가 확정/업그레이드되는 순간 다시 흐른다.
- 계속 흐름 (물리적 조사 = 7분의 본질): 서재 탐색 · 오브젝트 확대 · 시약 도포 · 피아노 줄 궤적 드래그 · 상처에 줄 대조 · 금고 다이얼 회전.
- 스스로 나가기: **서재 문을 클릭**하면 조사를 마치고 나간다. 타이머는 그 자리에서 멈춘다.
- 시간 초과: 타임아웃 연출이 나오고 **바로 추리(가설) 단계**로 넘어간다. 그 뒤로는 단서를 더 모을 수 없다. 분기는 그 시점에 가진 단서로 정해진다.

## 데이터 입력

- 실제 내용(할 일1.pdf → ScriptableObject 에셋)은 **M3 직전**에 넣는다. 로직이 정해지기 전에 넣으면 칸 구조가 바뀔 때마다 다시 고쳐야 한다.
- 백엔드는 테스트용 가짜 데이터, 클라이언트·QA는 실제 내용 입력과 대조를 맡는다.

## QA 기준

할 일1.pdf의 엔딩 조건 4개를 체크리스트로 쓴다. 예: "피아노 줄 업그레이드 안 함 + 조합 A → 엔딩 1".
제한 시간 명세의 시간 초과 분기도 넣는다: 겉보기 단서만 → 엔딩 1, 모순·부족 → 엔딩 2, 심층 단서 4종 + 비밀 편지 → 엔딩 3·4 선택.
로직은 단계마다 EditMode 테스트를 붙이고, QA는 화면과 흐름에 집중한다.
